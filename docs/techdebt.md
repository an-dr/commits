# Technical debt

| ID | Bug description | Source file | Test file |
| --- | --- | --- | --- |
| BUG-003 | Opening a repository reads and shapes its whole history inside one `on-message`, which the engine judges against a per-call wall-clock budget defaulting to 50ms. The call traps, the extension is quarantined, and the panel goes black mid-session -- indistinguishable from the startup failure of BUG-002, and reproducible simply by opening a repository. Mitigated by raising the budget to 20s (`Kernel::extension_call_timeout`), which is a ceiling, not a fix: the work still runs synchronously on the thread that owns the window, so a large repository freezes the UI for as long as it takes. Splitting the read into resumable chunks is the real answer. | `apps/commits/bones-adapter/src/commits-core.ts`, `apps/commits/host/src/main.rs` | `apps/commits/host/tests/component_load.rs` |
| BUG-002 | A startup extension that loads slower than its budget fails startup. The engine allows 1s by default; the host sets 30s (`Kernel::extension_load_timeout`) after 4/4 traps under CPU load and 0/8 idle on the same bytes. The component is now required (`Kernel::required_extension`), so a failure stops startup with a dialog naming the reason instead of a black window, but a machine slower than the allowance still cannot start. | `apps/commits/host/src/main.rs` | `vendor/bones/crates/bones-kernel/tests/engine.rs` |
| BUG-005 | The host serves both webview pages over a local `TcpListener` because bones' `PanelSource::Html` runs its custom-protocol handler on the window-owning thread -- the same thread busy loading the component -- so a panel opened that way stays blank for the whole wait the splash exists to cover. A `data:` URL renders but leaves the page at an opaque origin, where wry panics on any `window.ipc` call. The local server is correct, not redundant; retiring it means making that handler answer off the window thread, which is an upstream engine change (ADR-012). | `apps/commits/host/src/page.rs`, `apps/commits/host/src/splash.rs` | `apps/commits/host/src/page.rs` |
| BUG-009 | Reloading the component through the control channel (`POST /extensions/reload?name=commits`) runs its `init` again, which asks the web module to open the `commits/main` panel that still exists. The request fails with `panel already exists`, so the reloaded instance may not drive the panel the user sees. A reload confirms that a new build loads; using it still needs a restart. | `apps/commits/bones-adapter/src/commits-core.ts`, `apps/commits/host/src/main.rs` | None |
| BUG-008 | Watching a repository registers recursively, so it also walks build output the event filter then discards: about 20 seconds and 5,921 directories for this repository on Linux, of which only 834 matter. It runs off the engine's thread, so nothing freezes, but it costs background time and inotify descriptors. Pruning ignored directories and watching the rest non-recursively would cut it about sevenfold, but a non-recursive watch misses directories created later unless one is added for each, and getting that wrong loses events silently. | `crates/watcher/src/lib.rs` | `crates/watcher/src/tests.rs` |

Resolved entries leave this file; their fixes are in the [changelog](../CHANGELOG.md) and the git history.

## To upstream

Work Commits carries that would serve any bones application. Each item belongs in bones under [ADR-003](adr/ADR-003-treat-vendored-bones-as-read-only-upstream.md); once bones ships it, Commits deletes its own copy.

| Item | Benefit to other bones projects | Commits source |
| --- | --- | --- |
| Long extension calls off the window thread, or a resumable-work pattern for them (BUG-003) | Heavy guests stop freezing the window or tripping the call budget | `apps/commits/host/src/main.rs` (20s call budget) |
| Answer the web custom protocol off the window thread (BUG-005) | `PanelSource::Html` works while an extension loads, so apps need no local HTTP server for their pages | `apps/commits/host/src/page.rs` |
| A loading panel shown until the startup extension's panel opens | Every app with a large component gets a startup screen instead of a black window | `apps/commits/host/src/splash.rs` |
| A file log sink, and a dialog for a failed `run`, in windowed release builds | Release apps without a console keep a log and can tell the user why startup failed | `apps/commits/host/src/diagnostics.rs`, `apps/commits/host/src/main.rs` (`report_fatal`) |
| Let a reloaded extension reattach to the panels it already owns (BUG-009) | Hot reload works for web-panel apps, not only canvas ones | `apps/commits/host/src/main.rs` (extension controller) |
| A TypeScript guest package: the `Writer`/`Reader` codec, message types generated from `wire-format.json`, and a test against the conformance vectors | TypeScript guests share one checked codec instead of each copying the demo's `wire.ts` and tag numbers | `ipc/ts/codec.ts`, `ipc/ts/bones-messages.ts`, `ipc/ts/bones-vectors.test.ts`, `xtask/src/wire_types.rs` |
| Release packaging for apps using the upgrade module: version-payload ZIP, updater manifest with SHA-256, and a binary architecture check | Any self-updating app produces releases its installed copies accept, without writing its own packager | `xtask/src/package.rs` |
| Install from a built tree with the upgrade module's `version~instance` folders and pruning | Apps get a first install and side-by-side dev installs that match what the updater expects | `scripts/install.ps1` |
| Pruned recursive watching in `bones-kernel-watch` (BUG-008) | Every watcher user skips ignored directories instead of walking build output | `crates/watcher/src/lib.rs` |
