# Technical debt

| ID | Bug description | Source file | Test file |
| --- | --- | --- | --- |
| BUG-001 | Standalone startup begins evaluating the shared graph module before settings initialize its required global `viewState`, so module evaluation fails and only the static shell remains visible. | `apps/commits/web/src/main.ts` | `apps/commits/web/src/startup-order.test.ts` |
| BUG-003 | Opening a repository reads and shapes its whole history inside one `on-message`, which the engine judges against a per-call wall-clock budget defaulting to 50ms. The call traps, the extension is quarantined, and the panel goes black mid-session -- indistinguishable from the startup failure of BUG-002, and reproducible simply by opening a repository. Mitigated by raising the budget to 20s (`Engine::extension_call_timeout`), which is a ceiling, not a fix: the work still runs synchronously on the thread that owns the window, so a large repository freezes the UI for as long as it takes. Splitting the read into resumable chunks is the real answer. | `apps/commits/bones-adapter/src/commits-core.ts`, `apps/commits/host/src/main.rs` | `apps/commits/host/tests/component_load.rs` |
| BUG-002 | A startup extension that fails to load is non-fatal to the engine: it logs the error, keeps ticking, and nothing opens the panel, so the only symptom is a black window. There is no way to declare an extension required, so any future load failure presents the same way. Mitigated, not closed: the host writes `commits.log` and raises a dialog, and the load budget that caused the original failure is now set explicitly (`Engine::extension_load_timeout`, 30s, against a 1s engine default that trapped 4/4 under CPU load and 0/8 idle on the same bytes). A machine slower than the allowance still fails, and still only via the dialog. | `vendor/bones/core/runner/src/engine/builder.rs`, `apps/commits/host/src/main.rs` | `apps/commits/host/src/diagnostics.rs`, `vendor/bones/core/runner/src/engine/builder/tests.rs` |
