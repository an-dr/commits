# Technical debt

| ID | Bug description | Source file | Test file |
| --- | --- | --- | --- |
| BUG-003 | Opening a repository reads and shapes its whole history inside one `on-message`, which the engine judges against a per-call wall-clock budget defaulting to 50ms. The call traps, the extension is quarantined, and the panel goes black mid-session -- indistinguishable from the startup failure of BUG-002, and reproducible simply by opening a repository. Mitigated by raising the budget to 20s (`Engine::extension_call_timeout`), which is a ceiling, not a fix: the work still runs synchronously on the thread that owns the window, so a large repository freezes the UI for as long as it takes. Splitting the read into resumable chunks is the real answer. | `apps/commits/bones-adapter/src/commits-core.ts`, `apps/commits/host/src/main.rs` | `apps/commits/host/tests/component_load.rs` |
| BUG-002 | A startup extension that fails to load is non-fatal to the engine: it logs the error, keeps ticking, and nothing opens the panel, so the only symptom is a black window. There is no way to declare an extension required, so any future load failure presents the same way. Mitigated, not closed: the host writes `commits.log` and raises a dialog, and the load budget that caused the original failure is now set explicitly (`Kernel::extension_load_timeout`, 30s, against a 1s engine default that trapped 4/4 under CPU load and 0/8 idle on the same bytes). A machine slower than the allowance still fails, and still only via the dialog. | `vendor/bones/crates/bones-kernel/src/kernel/builder.rs`, `apps/commits/host/src/main.rs` | `apps/commits/host/src/diagnostics.rs`, `vendor/bones/crates/bones-kernel/src/kernel/builder/tests.rs` |
| BUG-005 | The host serves both webview pages over a local `TcpListener` because bones' `PanelSource::Html` runs its custom-protocol handler on the window-owning thread -- the same thread busy loading the component -- so a panel opened that way stays blank for the whole wait the splash exists to cover. A `data:` URL renders but leaves the page at an opaque origin, where wry panics on any `window.ipc` call. The local server is correct, not redundant; retiring it means making that handler answer off the window thread, which is an upstream engine change (ADR-012). | `apps/commits/host/src/page.rs`, `apps/commits/host/src/splash.rs` | `apps/commits/host/src/page.rs` |
| BUG-007 | The shared working-tree view has no distinct conflict-file status. Unmerged porcelain-v2 paths are listed as modified files so their conflict markers can be inspected; the existing operation banner and health line carry conflict information. A dedicated conflict marker or view is outside the integration scope. | `apps/commits/bones-adapter/src/mit/graph-backend.ts`, `packages/core/src/webview/changesPanelRender.ts` | `apps/commits/bones-adapter/src/commits-core.test.ts` |
| BUG-008 | Watching a repository registers recursively, so it also walks build output the event filter then discards: about 20 seconds and 5,921 directories for this repository on Linux, of which only 834 matter. It runs off the engine's thread, so nothing freezes, but it costs background time and inotify descriptors. Pruning ignored directories and watching the rest non-recursively would cut it about sevenfold, but a non-recursive watch misses directories created later unless one is added for each, and getting that wrong loses events silently. | `crates/watcher/src/lib.rs` | `crates/watcher/src/tests.rs` |

## Resolved

- BUG-001: startup evaluated the shared graph module before settings created its `viewState`, leaving only the static shell. `viewState` is now initialized before that module is imported, and `apps/commits/web/src/startup-order.test.ts` holds the order.
- BUG-004: Linux watch setup reported non-mutating access events as changes. Bones' watcher now drops them before they reach Commits.
- BUG-006: desktop registration moved to Bones’ desktop module; the local crate is removed. BUG-005 remains open because the current Bones release excludes the page-serving fix.
